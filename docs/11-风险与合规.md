# 11 · 风险与合规

**请先读完这一页再动手。**

---

## 1. 服务条款

把 App 内额度搬到 App 外使用，通常**违反服务商的服务条款**。

这不是本项目作者的法律意见，具体以你使用的服务商条款为准。
但风险是真实的，而且后果比大多数人预期的严重。

---

## 2. 封号风险的量级

| | 方案 B / 内核链路 | 方案 A / 直连网关 |
|---|---|---|
| 服务端看到的客户端 | 就是官方 App | 「第二客户端」 |
| 流量可区分性 | 与真人用 App **无法区分** | 特征明显 |
| 封号风险 | **低** | **较高** |

### 封禁是账号级的

> 封禁是账号级的 —— 官方 App 会一起失效，不只是反代。

你可能还能用反代跑得很好，结果某天早上打开官方 App 发现账号被禁了 ——
**App 内的额度、已经充的钱，全都一起没了。**

### 已知后果

- 返回码 `40109 current user is banned`
- 封禁多为**限时**（24h～7d），但**有永久的先例**
- 风控是**累计计数**的：
  - 连续错误签名的试探
  - 被拒后反复重试
  - 并发压测
  这些都会推高风险分

---

## 3. 降低风险的做法

按有效性排序：

### ① 调试时每次只发一个请求

单个 `40104`（签名错误）是无害的。**连续大量** 才会被判定为攻击。

```bash
# ❌ 不要这样
for i in $(seq 100); do curl ... ; done

# ✅ 一次一个，看返回码
curl ... ; echo $?
```

### ② 别并发压测，保持人类节奏

并发几十个请求在服务端看起来就像一个爬虫。

### ③ 别在主号上实验

用小号。**主号封了就什么都没了。**

### ④ 控制日用量

别当 7×24 主力通道用。如果要长期跑 —— 优先考虑内核链路。

### ⑤ 需要长期跑 → 降低客户端特征

走内核链路时，出站由 App 进程发出，流量与真人使用无法区分。
代价是不能注入自定义 tools。

**如果你必须用自己的工具链（agent 自己控制工具循环），就只能直连 —— 那就严格按上面 ①~④ 控制用量。**

## 4. 数据安全

### 本项目自己会碰到的敏感数据

| 数据 | 位置 | 风险 |
|---|---|---|
| 账号 token | `data/accounts.json`（加密） | **等同密码** |
| 加密密钥 | `data/.key` | 拿到就等于拿到所有 token |
| 渠道密钥 | `config/channel-key.txt` | 所有人共用，但也不该外传 |
| bundle 导出 | `data/account-*.bundle` | **等同密码** |
| 请求日志 | `data/requests.log` | 只记摘要，不含完整 body |
| 上游响应 | `data/requests.responses.log` | 含错误报文片段 |

### 本项目的处理

**✓ token 落盘加密**（AES-256-GCM）

**✓ 原子写**（临时文件 + rename）—— 崩溃不会留下半截凭据库

**✓ 请求日志只记摘要，不记完整 body**

```js
// 只记：模型、流式开关、消息结构、媒体类型和大小
summary: 'model=chat-flagshipAuto stream=true messages=2 roles=[user[str]] 媒体[image_url:data(52KB)]'
```

body 里可能有文件内容和对话内容 —— 不落盘。

**✓ 日志轮转**（超 2MB 保留最后 500 行）

**✓ 管理后台默认只听 `127.0.0.1`**

### 你要做的

- [ ] `data/` 目录不要进版本库（`.gitignore` 已排除）
- [ ] bundle 文件不要外传、不要放云盘同步目录
- [ ] 改 `0.0.0.0` 对外监听时，**一定**设一个强 `apiKey`
- [ ] 账号只用自己的
- [ ] 别把 `data/` 打包给别人

## 5. 逆向相关的合规边界

v1 目录里有 `_re/` 逆向工具链。它们是**研究工具**，用于还原协议行为。

- 这些工具**运行时不需要**，只用于研究
- 逆向的目的在本项目里是**理解协议以便自己实现中间层**，不是绕过任何保护机制
- 用它们分析你**自己机器上已安装并已登录**的软件
- 不要用它去分析或攻击他人的系统

---

## 6. 项目本身的性质

| | |
|---|---|
| 用途 | 研究桌面客户端的协议行为；在自己账号上搭自用中间层 |
| 依赖 | 你自己的账号、你自己安装的客户端 |
| 出站 | 所有请求都发往服务商自己的网关，不经过第三方 |
| 数据 | 全程本地，不上传任何遥测 |
| 第三方依赖 | **零**（只用 Node 内置模块） |

本项目**不收集、不上报任何数据**。没有遥测、没有崩溃上报、没有自动更新检查。

---

## 7. 给二次开发者的提醒

如果你基于这份代码做二次开发并公开发布：

1. **保留风险提示** —— 别让用户以为零风险
2. **不要打包凭据** —— 账号数据必须在用户本地
3. **默认监听 127.0.0.1** —— 对外监听要显式开启
4. **保持零依赖** —— 这是这个项目最大的安全优势之一
5. **别做批量/并发工具** —— 那是给别人递刀子

---

## 8. 一句话总结

> 在自己的机器、自己的账号上，谨慎、小量、清醒地使用。
> 记住封禁的是账号，不是反代。
