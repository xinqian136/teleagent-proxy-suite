# 03 · 凭证与账号池

桌面客户端的凭证不是静态的 —— 它会过期、会轮转、会 90 天硬失效。
中间层要长期无人值守跑，就必须自己管好这条链。

源码：`versions/v4/lib/account-manager/`、`versions/v4/lib/proxy/pool.js`、
`versions/v4/lib/proxy/refresher.js`、`versions/v4/lib/storage/`

---

## 1. 凭证从哪来

扫**数据目录**，不是安装位置：

```
%USERPROFILE%\.local\share\TeleAgent\users\v1_public_*/app-auth/token.json
```

> v1 早期扫的是安装位置，后来改成扫数据目录 —— 数据目录才是账号真正落盘的地方，
> 换版本、升级都不影响。

### 两种加密方案

`token.json` 里的 `encryptedToken` 有两种封装：

| scheme | 密钥在哪 | 能否跨机器 |
|---|---|---|
| `safe_storage` | `Local State` 里的 AES key，经 **DPAPI** 解密 | ❌ 绑定 Windows 用户 + 机器 |
| `local` | 同目录 `local-key`（纯随机文件） | ✅ 可复制 |

### 解密实现

```js
// safe_storage：密文布局 v10 | nonce(12) | ct | tag(16)
function decryptSafeStorage(b64, aesKey) {
  const b = Buffer.from(b64, 'base64');
  if (b.subarray(0, 3).toString('latin1') !== 'v10') throw new Error('非 v10 格式');
  const nonce = b.subarray(3, 15);
  const tag = b.subarray(b.length - 16);
  const ct = b.subarray(15, b.length - 16);
  const d = require('crypto').createDecipheriv('aes-256-gcm', aesKey, nonce);
  d.setAuthTag(tag);
  return Buffer.concat([d.update(ct), d.final()]).toString('utf8');
}

// local：密文布局 nonce(12) | ct | tag(16)
function decryptLocal(b64, key) {
  const b = Buffer.from(b64, 'base64');
  const nonce = b.subarray(0, 12);
  const tag = b.subarray(b.length - 16);
  const ct = b.subarray(12, b.length - 16);
  const d = require('crypto').createDecipheriv('aes-256-gcm', key, nonce);
  d.setAuthTag(tag);
  return Buffer.concat([d.update(ct), d.final()]).toString('utf8');
}
```

### safe_storage 的 AES key 走 DPAPI

`Local State` 文件里有一段 DPAPI 加密的 `os_crypt.encrypted_key`，
剥掉 `DPAPI` 前缀后用 DPAPI 解，得到真正的 AES key。实现见 `lib/dpapi.js`。

DPAPI 失败是**正常情况**，不是 bug —— 凭据本来就绑定当前 Windows 用户 + 机器。
换机器解不开，说明该账号需要走导入通道。

### 扫描结果带可迁移性标记

```js
rec.scheme = scheme;      // 'safe_storage' | 'local'
rec.portable = portable;  // local → true
rec.localKey = localKeyB64;  // 仅 local 方案有，供 export 用
```

导出时据此决定怎么打包：`local` 方案能带走，`safe_storage` 带不走
（目标机只能靠重新登录或从别的账号包导入）。

## 2. 账号记录模型

```js
{
  id: 'acc_xxx',                 // 本地 ID
  tenant: 'I7Kp2X',
  accountId: '1903017686270410753',
  accountName: '曾星熠',
  token: 'I7Kp2X:eyJhbGciOi...',  // 明文令牌（落盘时加密）
  status: 'active' | 'needsRelogin' | 'disabled',
  expiresAt: 1794991469,         // Unix 秒，JWT 的 exp
  absoluteExpiresAt: 1797553,    // Unix 秒，90 天硬期限（JWT 的 abs）
  source: 'scan' | 'import' | 'bundle',
  note: '', createdAt, updatedAt, lastUsedAt, lastError
}
```

`expiresAt` 和 `absoluteExpiresAt` 都来自 JWT payload：

```js
function fromToken(token, extra = {}) {
  const { tenant, payload } = parseToken(token);
  return {
    ...
    expiresAt: payload?.exp || null,
    absoluteExpiresAt: payload?.abs || null,
  };
}
```

### 可用性判定

```js
function evaluate(rec, now = Date.now()) {
  const sec = Math.floor(now / 1000);
  if (!rec.token) return { usable:false, reason:'no-token', status:NEEDS_RELOGIN };
  if (rec.expiresAt && sec >= rec.expiresAt)
    return { usable:false, reason:'expired', status:NEEDS_RELOGIN };
  if (rec.absoluteExpiresAt && sec >= rec.absoluteExpiresAt)
    return { usable:false, reason:'absolute-expired', status:NEEDS_RELOGIN };
  if (rec.status === STATUS.DISABLED)
    return { usable:false, reason:'disabled', status:DISABLED };
  return { usable:true, reason:null, status:ACTIVE };
}
```

**两个期限的区别很重要**：
- `expiresAt`（几小时）—— 可以续期
- `absoluteExpiresAt`（90 天）—— **续期也延长不了**，必须重新登录

## 3. 存储层

两种后端，接口一致：

| | `json-store.js` | `sqlite-store.js` |
|---|---|---|
| 依赖 | 无 | Node 22+ 内置 `node:sqlite` |
| 加密 | 整文件 AES-256-GCM | 逐字段 |
| 适合 | 单账号到几十个 | 大量账号 / 需要查询 |

默认用加密 JSON。密钥存在 `data/` 下的 `.key` 文件。

### 原子写

所有写入都是「临时文件 + rename」：

```js
save() {
  fs.mkdirSync(path.dirname(this.file), { recursive: true });
  const tmp = this.file + '.tmp';
  fs.writeFileSync(tmp, JSON.stringify(this._data, null, 2), 'utf8');
  fs.renameSync(tmp, this.file);      // ← rename 在同一卷上是原子的
}
```

**为什么重要**：续期轮转了 session，新 token 必须立刻落盘。
写到一半崩溃会留下半截 JSON，整个凭据库报废。
`rename` 是原子的 —— 要么旧文件，要么新文件，没有中间态。

### 加密格式

统一 `base64( nonce(12) | ciphertext | tag(16) )`，AES-256-GCM。
口令派生用 scrypt（N=16384, r=8, p=1），见 `lib/crypto.js`。

## 4. 账号池

`lib/proxy/pool.js`

### 轮询取号

```js
pick(opts = {}) {
  if (opts.accountId) { ... }        // 指定账号
  const list = this.usable();
  if (!list.length) return null;
  const r = list[this._cursor % list.length];   // ← 轮询
  this._cursor = (this._cursor + 1) % list.length;
  this._markUsed(r.id);
  return r;
}
```

轮询而不是随机，是为了让多个账号的用量分布均匀 —— 避免某一个账号被集中消耗。

### 失败上报

```js
reportFailure(id, err) {
  const fatal = err.fatal || [40112, 40113, 40115, 40116].includes(err.code);
  const patch = {
    status: fatal ? STATUS.NEEDS_RELOGIN : r.status,   // 终止性错误才摘账号
    lastError: `${err.code || err.status || '?'} ${err.message || ''}`.trim(),
    updatedAt: Date.now(),
  };
  ...
}
```

**只有终止性错误才把账号标记为需重登**。可重试的错误（40114 token 过期、
50005 暂时不可用）只记录错误信息，账号还在池里。

### 状态摘要

```js
summary() {
  return {
    total, usable, needsRelogin, disabled,
    expiringSoon,   // 24 小时内到期的
    deviceId, installId,
  };
}
```

## 5. 续期策略

`lib/proxy/refresher.js`

### 三个触发时机

```
① 定时：每 6 小时一轮，把 24 小时内到期的账号续掉
② 请求前：ensureFresh(rec) —— 拿到的账号不可用就先续
③ 请求失败：遇到 40114 / 40105 → 立刻续期并重试一次
```

### 错误分类

```js
const TERMINAL_CODES = [40112, 40113, 40115, 40116];  // 需重登
const RETRYABLE_CODES = [40114, 50005, 40105];        // 可重试
```

**连续失败 3 次 → 标记 needsRelogin**：

```js
if (fatal || n >= 3) {
  this._patch(rec.id, { status: STATUS.NEEDS_RELOGIN, ... });
  return { ok:false, reason:'needs-relogin', code };
}
```

### 拿到新 token 立刻落盘

```js
try {
  this._patch(rec.id, { token: r.token, status: STATUS.ACTIVE, ... });
  return { ok: true };
} catch (e) {
  // 写回失败：保留旧 token（降级），不要丢链子
  this.log(`[续期] 新 token 写回失败（${e.message}），保留旧 token`);
  return { ok: false, reason: 'persist-failed', error: e.message };
}
```

> 「宁可晚点死，也不能把链子彻底断掉」——
> 写回失败时保留旧 token（旧的可能还能用几分钟），比丢了好。

### 请求失败后的重试序列

`lib/proxy/server.js` 的 `handleInference`：

```
for (attempt = 0; attempt < maxAttempts; attempt++) {
  rec = pool.pick()                    // ① 换号
  fresh = refresher.ensureFresh(rec)    // ② 保鲜
  r = await chatCompletion(...)         // ③ 请求

  if (成功) return

  if (带图 && 模型不支持视觉 && 未降级) {
    改 model → chat-flash; attempt--; continue;      // ④ 视觉降级
  }

  if (可重试错误 && 还有次数) {
    rr = refresher.refreshOne(...)      // ⑤ 续期
    if (rr.ok) { attempt--; continue; }               //    同号再来一次
  }

  pool.reportFailure(fresh.id, err)     // ⑥ 标记，换下一个号
}
```

注意 `attempt--` 的用法：**降级和续期重试不消耗重试次数**，
只有「换号」才消耗。最多 3 次尝试（受可用账号数限制）。

## 6. 跨机迁移

### 导出 bundle

`account-manager/exporter.js` 支持 bundle / xlsx / csv。

bundle 里包含：账号 token + 渠道密钥 + 可选的 `local-key`。
**bundle 等同于账号密码**，别乱发。

xlsx / csv 是给「看一眼」的，不含 token 明文（或含脱敏版本），
主要用于人工核对账号状态。

### 导入

```js
importInto(store, path, { password });
```

导入后如果带了渠道密钥，自动写到 `config/channel-key.txt`：

```js
if (r.channelKey) {
  fs.writeFileSync(path.join(ctx.root, 'config', 'channel-key.txt'), r.channelKey, 'utf8');
}
```

### 目标机需要什么

| | 需要 | 不需要 |
|---|---|---|
| 目标机 | Node 18+、本项目文件夹、bundle 文件 | ~~装 TeleAgent~~、~~npm install~~ |

## 7. 自建时的检查清单

- [ ] 扫的是**数据目录**不是安装位置
- [ ] 区分 `safe_storage` / `local` 两种密文格式
- [ ] DPAPI 失败当成正常情况处理，不要当致命错误
- [ ] 落盘用「临时文件 + rename」保证原子性
- [ ] 续期拿到新 token **立刻**落盘
- [ ] 写回失败保留旧 token，不要丢
- [ ] 只有终止性错误才摘账号
- [ ] 区分 `exp`（可续）和 `abs`（不可续）
- [ ] bundle 视为密码级敏感数据
