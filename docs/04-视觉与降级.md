# 04 · 视觉与降级

图片能不能看，是这个项目里最反复的问题。分两层：

- **协议层**：图片块格式对不对、远程 URL 要不要转 base64 → [media.js](#1-媒体预处理)
- **能力层**：模型本身支不支持视觉 → [模型别名](#3-模型路由会变)

源码：`versions/v4/lib/proxy/media.js`、`versions/v4/lib/proxy/api.js`

---

## 1. 媒体预处理

### 网关只吃 base64

实测：远程 URL 会被网关拒（`1210`）。

但客户端（IDE Agent）通常把上传的图片存到对象存储，传过来的是**签名 URL**。
所以反代必须做一次「下载 → 转 base64」。

```js
// lib/proxy/media.js
const MAX_IMAGE_BYTES = 12 * 1024 * 1024;   // 12MB 上限
const TIMEOUT_MS = 30000;
```

### 处理三种块类型

```js
// OpenAI 风格
if (b.type === 'image_url') {
  const u = b.image_url && typeof b.image_url === 'object' ? b.image_url.url : b.image_url;
  if (isRemote(u)) { ...转 base64... }
}

// Responses 风格：image_url 可能是字符串，也可能是 {url}
if (b.type === 'input_image') {
  const u = typeof b.image_url === 'string' ? b.image_url : (b.image_url && b.image_url.url);
  if (isRemote(u)) { ...转 base64... }
}

// Anthropic 风格
if (b.type === 'image' && b.source && b.source.type === 'url' && isRemote(b.source.url)) {
  → { type:'image', source:{ type:'base64', media_type:'image/png', data:<base64> } }
}
```

### 只在真需要时才动手

```js
function isRemote(u)  { return typeof u === 'string' && /^https?:\/\//i.test(u); }
function isDataUrl(u) { return typeof u === 'string' && u.startsWith('data:'); }
```

已经是 `data:` 的不动。content 是纯字符串的也不动。
**不要无脑把所有 content 都遍历一遍再判断** —— 长会话里每张图都重下会拖垮延迟。

### 下载与转换

```js
async function toDataUrl(url) {
  const resp = await fetch(url, { signal: ac.signal, headers:{Accept:'image/*,*/*'}, redirect:'follow' });
  if (!resp.ok) return { ok:false, reason:`HTTP ${resp.status}` };
  const ct = resp.headers.get('content-type') || '';
  const buf = Buffer.from(await resp.arrayBuffer());
  if (!buf.length) return { ok:false, reason:'空响应' };
  if (buf.length > MAX_IMAGE_BYTES) return { ok:false, reason:`太大 ${...}MB` };
  const mime = /^image\//i.test(ct) ? ct.split(';')[0].trim() : 'image/png';
  return { ok:true, dataUrl:`data:${mime};base64,${buf.toString('base64')}`, bytes:buf.length };
}
```

失败时**保留原 URL 继续走**（不阻断请求），只记一条日志：

```js
notes.push(`远程图下载失败(${r.reason})，保留原URL`);
```

> 两种情况都要记 note —— 失败不记的话，后面根本无从排查。

## 2. 缓存的教训（已回滚）

v3 中途加过远程图缓存（同一批图在长会话里被反复下载），**用户实测反馈加了之后图片失效**，
于是回滚（commit `c4a45dc`）。

事后分析表明根因**不是缓存**，而是网关模型路由的变化。但这次回滚留下两个结论：

1. **改动图片相关逻辑风险很高** —— 回滚成本远高于收益。
2. 真正的解法是**模型别名**（下一节），不是缓存。

当前 `media.js` 与回滚后的 `b3d25c9` 版本字节级一致。

## 3. 模型路由会变

这是最反直觉的一点。

> 网关的模型路由是动态的：同一个模型名，有时支持视觉、有时被路由到只支持
> 文本的后端。

具体表现：

| 时机 | `chat-flagship` 的表现 |
|---|---|
| 上午 | 能看图，正常返回 |
| 下午 | `400 Model only supports text input` |
| 另一天 | 返回 200，但模型答「我无法查看图片」 |

**靠检测错误再降级不可靠** —— 报错形式会变，而且「200 但答不出」这种情况
连错误都检测不到。

## 4. 模型别名（v4 的解法）

显式映射，不靠猜：

```js
// lib/proxy/api.js
const MODEL_ALIASES = {
  'chat-flagshipAuto': {
    real: 'chat-flagship',        // 纯文本用旗舰
    vision: 'chat-flash',         // 带图用视觉稳定的
    desc: '自动：带图走 chat-flash，纯文本走 chat-flagship',
  },
};

function resolveModel(model, hasImage, overrides) {
  const alias = MODEL_ALIASES[model];
  if (!alias) return { name: model, aliased: false, switched: false };

  let target = alias.real;
  if (hasImage) {
    const visionModel = (overrides && overrides.visionModel) || alias.vision;
    target = visionModel || alias.real;
  }
  return { name: target, aliased: true, switched: target !== alias.real };
}
```

效果：

| 请求内容 | 实际发给网关 |
|---|---|
| 带图片 | `chat-flash`（视觉稳定） |
| 纯文本 | `chat-flagship`（旗舰） |

**客户端只管选 `chat-flagshipAuto`**，不用关心网关当天怎么路由。

### 怎么判断「有没有图」

```js
function bodyHasImage(body) {
  if (!body || typeof body !== 'object') return false;
  const scan = (c) => {
    if (!Array.isArray(c)) return false;
    return c.some((b) => b && typeof b === 'object' &&
      (b.type === 'image_url' || b.type === 'input_image' || b.type === 'image' || b.type === 'file'));
  };
  for (const m of (body.messages || [])) if (m && scan(m.content)) return true;
  for (const it of (body.input || [])) if (it && scan(it.content)) return true;
  return false;
}
```

三个数组都要扫 —— `messages` 是 OpenAI/Anthropic，`input` 是 Responses。

### 别名也出现在模型列表里

```js
function modelList(overrides) {
  const base = MODELS.map((id) => ({ id }));
  const aliases = Object.keys(MODEL_ALIASES).map((id) => ({
    id, alias: true,
    desc: MODEL_ALIASES[id].desc,
    vision_model: (overrides && overrides.visionModel) || MODEL_ALIASES[id].vision,
  }));
  return base.concat(aliases);
}
```

客户端拉 `/v1/models` 时能看到 `chat-flagshipAuto`，带 `alias: true` 标记。

## 5. 错误触发式降级（兜底）

别名是第一道防线，错误触发是第二道：

```js
const VISION_FALLBACK_MODEL = 'chat-flash';

function isVisionUnsupported(err) {
  const m = String((err && err.message) || '');
  return /only supports text input/i.test(m)
    || /not a VLM/i.test(m)
    || /\b20041\b/.test(m)
    || /unsupported content type 'image/i.test(m);
}
```

匹配到就换模型重试**一次**（不无限重试）：

```js
if (hasImage && visionFallback && !visionDowngraded && isVisionUnsupported(err)) {
  visionDowngraded = true;
  finalBody.model = VISION_FALLBACK_MODEL;
  log(`[推理] ${body.model} 不支持视觉（${err.code}），降级到 ${VISION_FALLBACK_MODEL} 重试`);
  recordResponse(url, 'vision-fallback', { from: body.model, to: VISION_FALLBACK_MODEL, code: err.code });
  attempt--;
  continue;
}
```

> `attempt--` 让降级重试不消耗重试次数。
> `visionDowngraded` 保证最多降级一次，不会死循环。

流式路径有同样的逻辑（`handleStream` 里）：

```js
if (hasImage && visionFallback && !visionDowngraded && isVisionUnsupported(e)) {
  visionDowngraded = true;
  gwBody.model = VISION_FALLBACK_MODEL;
  r.cleanup && r.cleanup();
  return await handleStream(url, body, res, true);   // ← 重试（已降级，不再降）
}
```

## 6. 配置项

在 Web 后台「设置」页，或 `config/settings.json`：

```json
{
  "proxy": {
    "visionFallback": true,        // 错误触发式降级开关
    "visionModel": "chat-flash"    // 带图时实际用的模型
  }
}
```

`visionModel` 决定 `chat-flagshipAuto` 带图时走哪个模型。
换 `chat-lite` 也能用 —— 只要那个模型视觉稳定。

## 7. 排查图片问题的顺序

按这个顺序查，能覆盖 95% 的情况：

```
① 请求里到底有没有图？
   → data/requests.log 里看摘要，媒体那栏会记：
      image_url:HTTP!     ← 说明是远程 URL（会被转 base64）
      image_url:data(52KB) ← 已经是 base64
      image:base64        ← Anthropic 风格
   → 如果压根没有「媒体[...]」，说明是**客户端没发图**

② 网关收到的是什么格式？
   → data/requests.responses.log 里看响应
   → 报 1210 → 网关没收到 base64，检查 media.js 是否生效

③ 网关说模型不支持视觉？
   → 报错信息匹配 isVisionUnsupported 吗
   → 不匹配 → 网关换了新的错误文案，需要补充正则
   → 匹配但没降级 → 检查 visionFallback 开关

④ 降级后还是不行？
   → 换个 visionModel（chat-lite / chat-flash 挨个试）
   → 试试不带图是不是正常 → 分离「协议问题」和「能力问题」
```

> `requests.log` 只记**摘要**，不记完整 body —— body 里可能有敏感内容。
> 但摘要里包含媒体类型和大小，足够定位。

## 8. 自建时的检查清单

- [ ] 网关只吃 base64 → 远程 URL 必须转
- [ ] 转 base64 要有大小上限和超时
- [ ] 转失败保留原 URL，别阻断请求
- [ ] 失败也要记日志
- [ ] 判断「有没有图」要扫 `messages` 和 `input` 两个数组
- [ ] 模型能力会变 → 别只靠错误检测，要有显式映射
- [ ] 降级最多一次，不能死循环
- [ ] 降级重试不消耗重试次数
