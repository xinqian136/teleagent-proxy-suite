## 1. 流式相关

### 复杂任务失败 / 长请求卡死 / 客户端超时

**最常见根因：`stream` 标志被吞。**

排查顺序：

```
① 看 data/requests.log 里那行的 stream= 值
   stream=-   → 客户端根本没带 stream 字段
   stream=false → 客户端要的是非流式
   stream=true  → 反代侧的问题

② stream=true 但客户端仍超时
   → 检查 handleStream 有没有被走到
   → 检查 res.flush() 是否调用
   → 检查前面有没有 nginx（X-Accel-Buffering: no）
```

代码上确认：

```js
if (parsed.stream === true) {
  return await handleStream(url, parsed, res);   // ← 必须有
}
```

以及流式分支里：

```js
res.write(Buffer.from(value));
if (res.flush) res.flush();     // ← 必须有
```

### 看起来不是流式（一次性全出）

| 原因 | 检查 |
|---|---|
| 没调 `res.flush()` | socket 攒数据 |
| 中间有反向代理缓冲 | 加 `X-Accel-Buffering: no` |
| 上游本身是伪流式 | 内核链路（v1 方案 B）本来就是伪流式 |

### 流式中途断开，客户端卡住

检查所有退出路径有没有 `res.end()`。异常路径也要：

```js
try { res.write(`data: {"error":{...}}\n\n`); } catch (_) {}
res.end();
```

## 2. 视觉相关

### 模型说「我无法查看图片」

```
① 看 requests.log 的「媒体[...]」栏
   没有这一栏 → 客户端压根没发图（不是反代的问题）
   image_url:HTTP!  → 是远程 URL，会被转 base64
   image_url:data(52KB) → 已是 base64

② 看 responses.log
   报 1210 → 网关没收到 base64，检查 media.js 是否生效
   报 "only supports text input" → 模型能力问题，走 ③
   报 200 但答不出 → 同样是模型能力问题，走 ③

③ 模型能力问题
   → 用 chat-flagshipAuto 别名（带图自动走 chat-flash）
   → 或在「设置」页把 visionModel 换成 chat-lite 试
   → 或确认 visionFallback 开关是开的
```

### 图片偶发失效（曾经发生过）

v3 中途加过远程图缓存，加完用户反馈图片失效，于是回滚（commit `c4a45dc`）。

事后分析：根因是**网关模型路由的变化**，不是缓存。
但结论是：**图片相关逻辑的改动风险很高，回滚成本远大于收益。**

排查这类问题时，先确认是不是网关那边变了 —— 隔一段时间重试，
如果表现不同，就是路由波动。

### Anthropic 客户端发图，图片丢失

Anthropic 的图片块格式是 `{type:'image', source:{type:'base64', media_type, data}}`。
如果转换层没处理，会被当未知块丢掉。

确认 `anthropicToGateway` 里有：

```js
case 'image': {
  const u = anthropicImageToDataUrl(b.source);
  if (u) mediaParts.push({ type: 'image_url', image_url: { url: u } });
  break;
}
```

## 3. 上游拒绝

### 403

**内容审核，不是协议问题。**

```
"请调用工具 get_weather 查询北京天气"        → 403
"Use the get_weather tool for city Beijing"  → 200
```

直连网关没有内容审核记录（走内核链路时有），某些措辞会被拦。换措辞即可。

### 40105（疑似攻击）

**立刻停手。** 不要重试、不要并发试。

风控是累计计数的，连续错误签名的试探会推高风险分。
等一段时间再用，或者换账号。

### 40109（账号被封）

账号级封禁，官方 App 也会一起失效。只能换号。

## 4. 签名相关

### 40101（missing security headers）

头名大小写错了。3.x 用 `X-SuperAgent-*`（**大写 A**），不是 `X-Superagent-*`。

逐项核对：

```
✓ Authorization: Bearer sk-<渠道密钥>
✓ X-Token: <tenant>:<JWT>        ← 完整形式，不是光 JWT
✓ X-Route-Target: ops-gateway
✓ X-Runtime-Env: ctyun_pc
✓ X-App-Version: 3.1.0
✓ X-SuperAgent-Timestamp: <秒>
✓ X-SuperAgent-Nonce: <uuid>
✓ X-SuperAgent-Device-Id
✓ X-SuperAgent-Install-Id
✓ X-SuperAgent-Sign-Version: v1
✓ X-SuperAgent-Signature
```

### 40104（invalid signature）

头齐了但签名不对。按这个表逐条查：

| 检查项 | 正确 | 常见错误 |
|---|---|---|
| scheme | `superagent-auth-v1` 全小写 | 大写了 |
| `ts` | 秒 | 用了毫秒 |
| bodyHash | 真正发出的 body 字节 | 算的是另一个对象 |
| 段数 | 第一轮 5 段 `/`，第二轮 7 段 `\n` | 段数不对 |
| 输出 | 小写 hex | 大写 |
| nonce | 每次新生成 | 复用了 |

**bodyHash 最容易错。** 确认签名和发送用的是**同一个字符串**：

```js
const payload = JSON.stringify(o.body);
const headers = buildHeaders({ ..., body: payload });
await fetch(url, { method:'POST', headers, body: payload });   // 同一个 payload
```

### 签名算法本体

见 [02 · 签名与鉴权](02-签名与鉴权.md)。

## 5. 账号与凭证

### 「没有可用账号」

```
看「账号」页的状态列：
  needsRelogin  → 必须在 TeleAgent 里重新登录，然后重新扫描
  expired       → 同上
  disabled      → 被手动禁用了，启用它
```

### 账号突然全部失效

```
① 检查是不是 90 天硬期限到了（absoluteExpiresAt）
   → 这个续期也救不了，必须重新登录
② 检查是不是被封（40109）
③ 检查 data/ 目录还在不在
   → 删了就断链了，要重新扫描 + 重新登录
```

### 续期一直失败

```
看日志的失败计数：
  连续 3 次失败 → 标记 needsRelogin
  单次失败      → 只是记录错误，账号还在池里
```

续期接口返回的错误码决定走向：

| 码 | 走向 |
|---|---|
| 40114 TOKEN_EXPIRED | 可续期 |
| 40112 / 40113 / 40115 / 40116 | 终止 → 需重登 |
| 50005 | 可重试 |

### 扫描不到账号

```
① TeleAgent 装了吗？登录过吗？
   → 没登录过就没有 users/v1_public_* 目录
② 数据目录路径对吗？
   → %USERPROFILE%\.local\share\TeleAgent
   → 可用 TA_DATA_DIR 环境变量指定
③ DPAPI 解密失败
   → safe_storage 绑定当前 Windows 用户 + 机器
   → 换机器解不开是正常的，走导入通道
```

## 6. 进程崩溃

### Web 后台莫名消失

```
① 大概率是 unhandledRejection
   Node 15+ 默认会终止进程

   检查管理路由有没有 await：
   if (p.startsWith('/api/admin/')) {
     return await handleAdmin(req, res, ...);   // ← 必须 await
   }

② 看是不是端口冲突
③ 看 data/requests.log 最后一行是什么
```

### 反代进程崩了但 Web 还活着

反代和 Web 同进程，反代崩了 Web 也应该崩。
如果 Web 活着但反代不在，查 `manager.status()` 的 `error` 字段。

## 7. 环境问题

### 端口被占用

```cmd
netstat -ano | findstr :8793
tasklist /FI "PID eq <PID>"
```

或者改端口（Web 后台「设置」页，或 `config/settings.json`）。

### Node.js not found

装 Node 18+。v3/v4 有个特点：**不需要 `npm install`**（零第三方依赖）。

### 内核起不来（v1 方案 B）

```
最常见：%LOCALAPPDATA%\teleagent-updater\installer.exe 存在
→ App 自动下载的更新包，启动时差分更新失败后静默退出
→ 改名成 installer.exe.disabled

其它：
  super-agent-code/bundled/plugin 缺失
  沙箱拦 reg.exe（是 WARN，不致命）
  App 继承了 HTTP_PROXY → 启动前清掉
```

### v3/v4 端口冲突

v3 用 8792/8795，v4 用 8793/8796，刻意错开。同时装不会撞。

但**不要同时跑同一个账号** —— 同一 token 两处用，有封号风险。

## 8. 协议转换

### Anthropic 客户端报「type 类型错误」/ 1214

网关只认 OpenAI 格式的块。Anthropic 的块没转干净。

逐项核对 `anthropicToGateway`：

```
✓ system → messages[0].role='system'
✓ image → image_url（base64 data URL）
✓ tool_use → assistant.tool_calls[]
✓ tool_result → {role:'tool', tool_call_id}
✓ document → 文本降级
✓ thinking → 丢弃
```

### 模型完全不记得上下文

```
① Anthropic → 检查 system 是不是顶层字段，有没有被漏
② Responses  → 检查 instructions 有没有转成 system 消息
③ 检查 content 数组是不是被过滤过
   （只留 text 会丢掉 tool_result → 工具循环断裂 → 失忆）
```

### 工具调用不来 / 工具结果不被接受

```
① Anthropic 的 tool_use 要变成 assistant.tool_calls
② Anthropic 的 tool_result 要变成 role:'tool' 消息
③ tool_result.content 必须是字符串（数组要 join）
④ tool_calls[].function.arguments 是 JSON 字符串，不是对象
```

```json
{"t":1758345600000,"path":"/v1/chat/completions","method":"POST",
 "summary":"model=chat-flagshipAuto stream=true messages=2 roles=[user[str],assistant[str]] 媒体[image_url:HTTP!]"}
```

一眼能看出：模型名对不对、流式开没开、有没有图、图片是 URL 还是 base64。

## 10. 终极排查手段

### 单独测上游

绕开反代，直接用最小请求打网关，隔离「协议问题」和「反代问题」：

```bash
curl -X POST https://agent.teleai.com.cn/superCowork/sapi/api/v1/chat/completions \
  -H "Authorization: Bearer sk-xxx" \
  -H "X-Token: tenant:eyJ..." \
  -H "X-Route-Target: ops-gateway" \
  -H "X-Runtime-Env: ctyun_pc" \
  -H "X-App-Version: 3.1.0" \
  -H "X-SuperAgent-Timestamp: <秒>" \
  -H "X-SuperAgent-Nonce: <uuid>" \
  -H "X-SuperAgent-Device-Id: xxx" \
  -H "X-SuperAgent-Install-Id: xxx" \
  -H "X-SuperAgent-Sign-Version: v1" \
  -H "X-SuperAgent-Signature: <签名>" \
  -H "Content-Type: application/json" \
  -d '{"model":"chat-flash","messages":[{"role":"user","content":"你好"}]}'
```

⚠️ 调试时**每次只发一个请求**。连续大量失败会被判攻击。

### 二分定位

把反代的各个环节逐个短路：

```
① 只调 media.js，不调签名 → 确认图片预处理不炸
② 调签名但不调上游 → 确认签名不抛异常
③ 全链路但用纯文本 → 确认基础通路
④ 加图 → 确认图片链路
⑤ 加 tools → 确认工具链路
```

哪一步开始出错，问题就在那一步。
