# 07 · 自建中间层指南

**这份文档的目标是让你自己写一个，不是让你用我们这份。**

按顺序读，每一步都能独立验证。做完全部，你就有一个自己的中间层，
而且知道每一行代码为什么在那里。

如果上游不是 TeleAgent，把 [01](01-协议转换.md)、[02](02-签名与鉴权.md)、
[05](05-流式与SSE.md) 当**格式模板**（照抄结构，替换内容）；
把 [03](03-凭证与账号池.md)、[04](04-视觉与降级.md) 当**反面教材清单**照着避坑。

---

## 第 0 步：先想清楚要解决什么

写代码之前，明确三件事：

```
① 上游是什么？      它的协议、鉴权方式、错误码
② 下游要接谁？      OpenAI？Anthropic？两者都要？
③ 稳定性要求多高？  自己用（能手动重启）vs 长期跑（要自愈）
```

本项目对应：

| | 答案 |
|---|---|
| 上游 | TeleAgent 云网关，OpenAI 格式 + 双轮 HMAC 签名 |
| 下游 | OpenAI / Anthropic / Responses 三种协议都要 |
| 稳定性 | 长期跑 —— 凭证自续期、账号池、故障降级 |

**如果你的场景是「自己用、能手动重启」，可以跳过第 4、5 步。**
先做出最小闭环，再按需加固 —— 这是本项目 v1 → v4 的真实演进路径。

## 第 1 步：最小闭环（半天）

目标：一个能应答纯文本的 HTTP 服务。

### 1.1 骨架

```js
// server.js
const http = require('http');

const server = http.createServer(async (req, res) => {
  const url = (req.url || '').split('?')[0];
  if (req.method === 'GET' && url === '/health') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    return res.end(JSON.stringify({ ok: true }));
  }
  if (req.method === 'POST' && url === '/v1/chat/completions') {
    const body = await readBody(req);
    const parsed = JSON.parse(body);
    // → 第 2 步：转发到上游
    return res.end('{}');
  }
  res.writeHead(404); res.end();
});

server.listen(8790, '127.0.0.1');
```

```js
function readBody(req) {
  return new Promise((resolve, reject) => {
    const chunks = [];
    req.on('data', (c) => chunks.push(c));
    req.on('end', () => resolve(Buffer.concat(chunks).toString('utf8')));
    req.on('error', reject);
  });
}
```

### 1.2 转发到上游

```js
const resp = await fetch(UPSTREAM_URL, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', ...upstreamHeaders(parsed) },
  body: JSON.stringify(parsed),      // ★ 同一个字符串，签名和发送都用它
});
const text = await resp.text();
res.writeHead(resp.status, { 'Content-Type': 'application/json' });
res.end(text);                      // ★ 原样返回，不重建
```

### 1.3 验证

```bash
curl http://127.0.0.1:8790/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"chat-flagship","messages":[{"role":"user","content":"你好"}]}'
```

✅ **通过标准**：能返回一段正常回答。

### 这一步最容易犯的错

- **重建响应 body**。网关返回什么就返回什么。重建会丢 `reasoning_content`、
  `usage` 细节、自定义字段。
- **忘了 `Content-Length` 或用了 chunked**。用 `res.end(text)` 时 Node 会自动处理，
  但如果你手动 `writeHead` 又 `write` 又 `end`，要自己算长度。

## 第 2 步：加上鉴权（1 小时）

上游要签名。下游要不要鉴权看场景 —— 监听 `127.0.0.1` 时本地不校验也常见，
但一旦暴露到局域网就必须有。

### 2.1 下游鉴权

```js
const token = (req.headers.authorization || '').startsWith('Bearer ')
  ? req.headers.authorization.slice(7).trim()
  : String(req.headers['x-api-key'] || '').trim();

if (apiKey && token !== apiKey) {
  return sendJSON(res, 401, { error: { message: '无效的 API Key', type: 'authentication_error' } });
}
```

> **两种头都认** —— `Authorization: Bearer` 是 OpenAI 惯例，`x-api-key` 是 Anthropic 惯例。
> 只认一种的话，另一种客户端就得改配置。

### 2.2 CORS（浏览器端调试用）

```js
res.setHeader('Access-Control-Allow-Origin', '*');
res.setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization, x-api-key, anthropic-version');
res.setHeader('Access-Control-Allow-Methods', 'GET, POST, OPTIONS');
if (method === 'OPTIONS') { res.writeHead(204); res.end(); return; }
```

### 2.3 验证

```bash
# 不带 key → 401
curl http://127.0.0.1:8790/v1/chat/completions -d '{...}'
# 带错 key → 401
curl -H "Authorization: Bearer wrong" http://127.0.0.1:8790/v1/chat/completions -d '{...}'
# 带对 key → 200
```

## 第 3 步：流式（半天）

**这一步是最容易做出「复杂任务失败」的地方。**

### 3.1 分流

```js
if (parsed.stream === true) {
  return await handleStream(parsed, res);
}
```

**关键**：`stream` 标志绝不能吞掉。之前 v3 之前的版本就是这里出的问题 ——
客户端请求流式，反代把标志丢了，客户端等一个永远不会来的流，
简单请求靠超时兜底还能过，复杂任务直接失败。

### 3.2 真流式转发

```js
async function handleStream(body, res) {
  const resp = await fetch(UPSTREAM_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Accept: 'text/event-stream', ...authHeaders(body) },
    body: JSON.stringify({ ...body, stream: true }),
  });

  if (!resp.ok || !resp.body) {
    // 流还没开始 → 还能改状态码
    const text = await resp.text();
    res.writeHead(resp.status, { 'Content-Type': 'application/json' });
    return res.end(text);
  }

  res.writeHead(200, {
    'Content-Type': 'text/event-stream; charset=utf-8',
    'Cache-Control': 'no-cache',
    'Connection': 'keep-alive',
    'X-Accel-Buffering': 'no',
  });

  const reader = resp.body.getReader();
  try {
    for (;;) {
      const { done, value } = await reader.read();
      if (done) break;
      res.write(Buffer.from(value));     // 原始字节透传
      if (res.flush) res.flush();        // ← 别攒着
    }
  } catch (e) {
    try { res.write(`data: {"error":{"message":"${e.message}"}}\n\n`); } catch (_) {}
  }
  res.end();
}
```

### 3.3 三个必须注意的点

| 点 | 不做会怎样 |
|---|---|
| `res.flush()` 判存在再调 | 数据攒在 socket 里，客户端看不到「打字机效果」 |
| `X-Accel-Buffering: no` | 前面有 nginx 时被缓冲，流式变伪流式 |
| 原始字节透传 | 自己 decode/re-encode 可能破坏分片边界 |

### 3.4 验证

```bash
curl -N http://127.0.0.1:8790/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"chat-flagship","stream":true,"messages":[{"role":"user","content":"数到20"}]}'
```

✅ **通过标准**：数字一个一个出现，不是等 20 秒后一次全出。

## 第 4 步：协议适配（1-2 天）

只有当你的客户端说的是别的协议时才需要这一步。

完整字段级映射见 [01 · 协议转换](01-协议转换.md)。这里只给最小骨架。

### 4.1 Anthropic → OpenAI 的骨架

```js
function anthropicToGateway(body) {
  const msgs = [];

  // ★ system 是顶层字段，漏了模型就失忆
  if (body.system) {
    msgs.push({ role: 'system', content: typeof body.system === 'string'
      ? body.system
      : body.system.map((b) => b.text || '').join('\n') });
  }

  for (const m of body.messages || []) {
    msgs.push(...convertMessage(m));
  }
  return { model: body.model || 'chat-flagship', messages: msgs };
}

function convertMessage(m) {
  const role = m.role === 'assistant' ? 'assistant' : 'user';
  if (typeof m.content === 'string') return [{ role, content: m.content }];

  const text = [], media = [], toolCalls = [], toolResults = [];

  for (const b of m.content || []) {
    switch (b.type) {
      case 'text': text.push(b.text || ''); break;
      case 'image': {
        const u = b.source?.type === 'base64'
          ? `data:${b.source.media_type || 'image/png'};base64,${b.source.data}`
          : b.source?.url;
        if (u) media.push({ type: 'image_url', image_url: { url: u } });
        break;
      }
      case 'tool_use':
        toolCalls.push({ id: b.id, type: 'function',
          function: { name: b.name, arguments: JSON.stringify(b.input || {}) } });
        break;
      case 'tool_result':
        toolResults.push({ role: 'tool', tool_call_id: b.tool_use_id || b.id,
          content: stringify(b.content) });
        break;
      case 'thinking': break;              // 上游不认，丢弃
      default:
        if (b.text) text.push(b.text);
    }
  }

  const out = [];
  out.push(...toolResults);                // 工具结果先于文本
  const t = text.join('\n');
  if (media.length) {
    const rec = { role, content: [{ type: 'text', text: t }, ...media] };
    if (toolCalls.length) rec.tool_calls = toolCalls;
    out.push(rec);
  } else {
    const rec = { role, content: t };
    if (toolCalls.length) rec.tool_calls = toolCalls;
    out.push(rec);
  }
  return out;
}
```

### 4.2 两条铁律

**① content 数组里的块不能过滤。**

```js
// ❌ 只保留 text，会丢掉 tool_result / image / input_file
const content = m.content.filter((c) => c.type === 'text');

// ✅ 数组原样保留，只处理非数组的情况
```

工具结果丢了 → 工具循环断裂 → 模型失忆 → 行为异常。

**② 工具调用和工具结果要拆成不同形态。**

Anthropic 把它们都放在 content 里，OpenAI 分开放。不拆的话上游收到
无法解析的块，直接报「type 类型错误」。

### 4.3 验证

至少测这 5 个场景，每个都用 OpenAI 和 Anthropic 各跑一遍：

```
1. 纯文本一问一答
2. 带图片问「图里有什么」
3. 带 tools 的完整工具循环（模型调工具 → 你执行 → 回灌 → 模型总结）
4. stream: true
5. 多轮对话（保留上一轮 assistant 消息）
```

## 第 5 步：凭证自管理（2-3 天）

如果上游凭证会过期，这一步决定你的中间层能活多久。

### 5.1 凭证模型

```js
{
  id, token, status,          // active | needsRelogin | disabled
  expiresAt,                 // Unix 秒，可续
  absoluteExpiresAt,         // Unix 秒，不可续（硬期限）
  lastError, updatedAt,
}
```

从 JWT 里读有效期：

```js
const seg = token.split(':')[1].split('.');
const payload = JSON.parse(Buffer.from(seg[1], 'base64url').toString('utf8'));
// payload.exp → expiresAt
// payload.abs → absoluteExpiresAt
```

### 5.2 三层续期触发

```
① 定时：每 6 小时一轮，把 24 小时内到期的续掉
② 请求前：ensureFresh() —— 拿到的凭证不可用就先续
③ 请求失败：遇到「过期」类错误 → 立刻续期并重试
```

### 5.3 错误分类

```js
const TERMINAL = ['需重登类错误码'];   // 续期也救不回来 → 标记
const RETRYABLE = ['过期类错误码'];     // 续期能救 → 重试
```

### 5.4 拿到新 token 立刻落盘，且原子写

```js
// 续期会轮转 session，不落盘 = 丢链子
function save(records) {
  const tmp = file + '.tmp';
  fs.writeFileSync(tmp, JSON.stringify(records, null, 2), 'utf8');
  fs.renameSync(tmp, file);     // ← 原子
}
```

写回失败**保留旧凭证**，不要丢：

```js
try {
  save(newRecords);
} catch (e) {
  // 保留旧 token 降级 —— 宁可晚点死，也不能把链子彻底断掉
  return { ok: false, reason: 'persist-failed' };
}
```

### 5.5 验证

```bash
# 手动把 expiresAt 改到过去，观察是否自动续期
# 停掉上游，观察是否切到下一个账号
```

## 第 6 步：多账号池（1 天）

单个凭证撑不住长期运行 —— 会有额度、频率、封禁各种限制。

### 6.1 轮询取号

```js
pick() {
  const list = this.usable();
  if (!list.length) return null;
  const r = list[this._cursor % list.length];
  this._cursor = (this._cursor + 1) % list.length;
  return r;
}
```

轮询而非随机 —— 让用量分布均匀。

### 6.2 失败分类处理

```js
for (let attempt = 0; attempt < maxAttempts; attempt++) {
  const rec = pool.pick();
  const fresh = await refresher.ensureFresh(rec);
  const r = await call(fresh);

  if (r.ok) return r;

  if (isRetryable(r.code)) {          // 可续期 → 同号重试
    if (await refresher.refreshOne(fresh.id)) { attempt--; continue; }
  }

  pool.reportFailure(fresh.id, r);    // 换下一个号
}
```

**注意 `attempt--`** —— 续期重试和降级重试不消耗次数，只有「换号」消耗。

### 6.3 可用性判定

```js
function usable(rec, now = Date.now()) {
  const sec = Math.floor(now / 1000);
  if (!rec.token) return false;
  if (rec.expiresAt && sec >= rec.expiresAt) return false;
  if (rec.absoluteExpiresAt && sec >= rec.absoluteExpiresAt) return false;
  if (rec.status === 'disabled') return false;
  return true;
}
```

### 6.4 验证

加 3 个账号，其中一个手动设为过期。发 5 个请求，
观察日志是否：跳过过期的 → 用可用的 → 失败时换号。

## 第 7 步：能力适配（1-2 天）

上游的能力边界和客户端的预期不一定对得上。这是「能跑但不对」的根源。

### 7.1 媒体：上游只吃 base64

```js
if (isRemote(url)) {
  const buf = await download(url);
  // 大小上限 + 超时
  block = { type:'image_url', image_url:{ url: `data:${mime};base64,${buf.toString('base64')}` } };
}
```

失败时**保留原 URL 继续走**，只记日志 —— 不阻断请求。

### 7.2 模型能力会变 → 用显式别名

这是本项目最重要的一条经验：

> 上游的模型路由是动态的。同一个模型名，有时支持视觉、有时被路由到只支持
> 文本的后端。表现形式还会变 —— 可能报 `400 only supports text input`，
> 也可能**返回 200 但模型答「我无法查看图片」**。

**靠检测错误再降级不可靠。** 必须有显式映射：

```js
const ALIASES = {
  'my-model-auto': {
    real: 'my-model',          // 纯文本
    vision: 'my-vision-model',  // 带图
  },
};

function resolveModel(model, hasImage, overrides) {
  const a = ALIASES[model];
  if (!a) return { name: model, aliased: false };
  const target = hasImage ? ((overrides && overrides.visionModel) || a.vision) : a.real;
  return { name: target, aliased: true, switched: target !== a.real };
}
```

错误触发式降级作为**兜底**保留，但最多一次：

```js
if (hasImage && !downgraded && isUnsupported(err)) {
  downgraded = true;
  body.model = FALLBACK_MODEL;
  attempt--;
  continue;
}
```

### 7.3 判断「有没有图」

```js
function bodyHasImage(body) {
  const scan = (c) => Array.isArray(c) && c.some((b) => b &&
    ['image_url','input_image','image','file'].includes(b.type));
  return (body.messages || []).some((m) => m && scan(m.content))
      || (body.input || []).some((i) => i && scan(i.content));
}
```

**`messages` 和 `input` 都要扫** —— 不同协议用不同的字段名。

### 7.4 验证

```
① 带图问「图里是什么」→ 应该能答对
② 故意把别名指向不支持视觉的模型 → 应该自动降级成功
③ 上游返回「不支持视觉」错误 → 应该降级重试
```

## 第 8 步：可观测性（1 天）

出问题时，第一件事是知道「客户端到底发了什么」。

### 8.1 记请求摘要，不记完整 body

```js
function recordRequest(pathname, method, j) {
  const parts = [];
  parts.push('model=' + (j.model || '-'));
  parts.push('stream=' + (j.stream === undefined ? '-' : j.stream));
  if (j.messages) {
    parts.push('messages=' + j.messages.length);
    const roles = j.messages.map((m) => {
      const kind = Array.isArray(m.content)
        ? '[' + m.content.length + '块:' + m.content.map((c) => c.type).join('+') + ']'
        : 'str';
      return m.role + kind + (m.tool_calls ? '+tc' : '') + (m.tool_call_id ? '+tcid' : '');
    });
    parts.push('roles=[' + roles.join(',') + ']');
  }
  // 媒体细节 —— 定位「传图失败」的关键
  const media = [];
  const scanContent = (c) => {
    if (!Array.isArray(c)) return;
    for (const b of c) {
      if (!b || typeof b !== 'object') continue;
      if (b.type === 'image_url' || b.type === 'input_image') {
        const u = typeof b.image_url === 'string' ? b.image_url : (b.image_url && b.image_url.url) || '';
        media.push('image_url:' + (u.startsWith('data:') ? 'data(' + Math.round(u.length/1024) + 'KB)'
          : u.startsWith('http') ? 'HTTP!' : (u ? u.slice(0,30) : '空')));
      } else if (b.type === 'image') {
        media.push('image:' + ((b.source || {}).type || '?'));
      }
    }
  };
  for (const m of (j.messages || [])) scanContent(m.content);
  for (const it of (j.input || [])) scanContent(it && it.content);
  if (media.length) parts.push('媒体[' + media.join(',') + ']');

  fs.appendFileSync(logFile, JSON.stringify({ t:Date.now(), path:pathname, method, summary:parts.join(' ') }) + '\n');
}
```

**只记摘要，不记完整 body** —— body 里可能有文件内容和敏感信息。
但摘要里包含媒体类型和大小，足够定位问题。

### 8.2 记上游响应

出问题时能直接看到上游说了什么：

```js
function recordResponse(pathname, kind, info) {
  fs.appendFileSync(respLogFile, JSON.stringify({ t:Date.now(), path:pathname, kind, ...info }) + '\n');
}
```

### 8.3 日志文件轮转

```js
if (fs.statSync(logFile).size > 2 * 1024 * 1024) {
  const lines = fs.readFileSync(logFile, 'utf8').trim().split('\n');
  fs.writeFileSync(logFile, lines.slice(-500).join('\n') + '\n');
}
```

## 第 9 步：管理界面（可选，2-3 天）

命令行改配置对非技术用户不友好。本项目 v3 加了 Web 后台。

### 9.1 单进程三路由

```js
if (p === '/' || p === '/index.html') return serveFile(res, 'public/index.html');
if (p.startsWith('/api/admin/')) return await handleAdmin(req, res, ...);
if (p.startsWith('/v1/')) return await proxyForward(req, res, ...);
```

### 9.2 反代生命周期托管

```js
class ProxyManager {
  async start() { /* 建 server → listen → 启续期循环 */ }
  async stop()  { /* 关 server → 停续期循环 */ }
  async restart() { await this.stop(); await sleep(500); return this.start(); }
}
```

改端口 / API Key → 调 `restart()` → 立即生效，不用重启整个后台。

### 9.3 反代与后台同进程

有意为之：

> 避免两个独立进程各管一份凭据、互相踩。

Web 关了反代也关 —— 符合直觉。

### 9.4 反向代理

管理后台自己也能当反代入口 —— `/v1/*` 转发给内部反代服务。
实现上把请求伪造后 emit 给内层 server：

```js
const fakeReq = Object.create(req);
fakeReq.url = p + (url.search || '');
fakeReq.method = method;
fakeReq.headers = { ...req.headers, 'content-length': body ? String(body.length) : '0' };
fakeReq.on = (ev, cb) => {
  if (ev === 'data') setImmediate(() => cb(body));
  if (ev === 'end') setImmediate(() => cb());
  return fakeReq;
};
inst.server.emit('request', fakeReq, res);
```

### 9.5 一个容易踩的坑

```js
// ❌ 不 await：handler 里的异步异常会变成 unhandledRejection，
//    Node 15+ 默认终止进程（后台会「莫名消失」）
if (p.startsWith('/api/admin/')) {
  return handleAdmin(req, res, ...);
}

// ✅
if (p.startsWith('/api/admin/')) {
  return await handleAdmin(req, res, ...);
}
```
