# 06 · 部署与运维

## 1. 环境要求

| 项 | v1 | v2+ | 说明 |
|---|---|---|---|
| Node.js | 18+ | 18+ | **零第三方依赖**，只用内置模块 |
| Python | 需要 | 不需要 | 仅 v1 的 sessionKey 逆向脚本用 |
| TeleAgent | 需要 | 不需要（可迁移） | 提供凭据与渠道密钥 |
| 平台 | Windows | Windows | DPAPI 依赖 Windows；协议层是纯 Node |
| SQLite 存储 | — | Node 22+ | 可选，默认加密 JSON |

---

## 2. 端口规划

不同版本**不要同时跑同一个账号**（同一 token 两处用，有封号风险）。

| 版本 | 反代端口 | Web 后台 | 计划任务名 |
|---|---|---|---|
| v1 | 8788（内核链路）/ 8790（直连） | — | — |
| v2 | 8792 | — | — |
| v3 | 8792 | 8795 | `TeleAgent Proxy V3` |
| v4 | **8793** | **8796** | `TeleAgent Proxy V4` |

v3 和 v4 端口刻意错开，同时装不会撞端口。

---

## 3. 安装与启动（v4）

### 3.1 源码

```bash
git clone https://github.com/xinqian136/teleagent-proxy-suite.git
cd teleagent-proxy-suite/versions/v4
```

### 3.2 启动

```cmd
:: 双击 启动后台.cmd
:: 或手动：
node bin\tav3.js web
```

浏览器会自动打开 `http://127.0.0.1:8796/`。

### 3.3 首次配置

```
① 「账号」页 → 点「扫描本机」
   → 自动找到 TeleAgent 的账号，列出状态和有效期
② 「反代」页 → 点「启动」
   → 日志出现 [反代] 已启动 http://127.0.0.1:8793/v1
③ 「概览」页 → 点「复制配置」
   → 得到三行，粘到你的客户端
```

### 3.4 客户端配置

```
Base URL : http://127.0.0.1:8793/v1
API Key  : teleagent-local
Model    : chat-flagshipAuto
```

各客户端具体填法：

| 客户端 | 在哪填 |
|---|---|
| Cherry Studio | 设置 → 模型服务 → 添加「OpenAI 兼容」服务 |
| Cline / Roo Code | 设置 → API Provider → OpenAI Compatible |
| Cursor | 设置 → Models → OpenAI API Key → Override Base URL |
| Claude Code | `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` |
| WorkBuddy | 设置 → 自定义模型 / OpenAI 兼容 |

## 4. 配置项全表

`config/settings.json`，或 Web 后台「设置」页改（改完热生效）。

```json
{
  "web": {
    "port": 8796,
    "host": "127.0.0.1",
    "openBrowser": true
  },
  "proxy": {
    "port": 8793,
    "host": "127.0.0.1",
    "apiKey": "teleagent-local",
    "autoStart": true,
    "paused": false,
    "visionFallback": true,
    "visionModel": "chat-flash"
  },
  "storage": "json",
  "refresher": {
    "intervalMinutes": 360,
    "aheadHours": 24
  },
  "appVersion": "3.1.0"
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `web.port` | 8796 | 管理后台端口 |
| `web.host` | `127.0.0.1` | 改 `0.0.0.0` 可局域网访问 |
| `proxy.port` | 8793 | 反代端口 |
| `proxy.host` | `127.0.0.1` | 同上 |
| `proxy.apiKey` | `teleagent-local` | 反代鉴权密钥，改了热重启生效 |
| `proxy.autoStart` | `true` | 后台启动时自动起反代 |
| `proxy.paused` | `false` | **持久化**暂停，重启后台也不自动起 |
| `proxy.visionFallback` | `true` | 视觉不支持时自动降级 |
| `proxy.visionModel` | `chat-flash` | 带图时实际用的模型 |
| `storage` | `json` | `json` 或 `sqlite` |
| `refresher.intervalMinutes` | 360 | 续期检查间隔（分钟） |
| `refresher.aheadHours` | 24 | 提前多久续期 |
| `appVersion` | `3.1.0` | 参与签名，服务端只校验格式 |

### 热重载规则

改了 `proxy.port` / `proxy.apiKey` / `proxy.visionFallback` / `proxy.visionModel`
→ 反代**自动重启**生效，不用重启后台。

```js
if (before.port !== after.port || before.apiKey !== after.apiKey
    || before.visionFallback !== after.visionFallback
    || before.visionModel !== after.visionModel) {
  if (manager.isRunning()) { const r = await manager.restart(); restarted = true; }
}
```

## 5. 暂停与恢复

三种粒度：

| 想做什么 | 怎么做 | 重启后台后 |
|---|---|---|
| 暂停反代（后台还在） | 网页「反代」页 → 暂停 | **仍然暂停**（持久化） |
| 临时停止反代 | 网页「反代」页 → 停止 | 会自动起来 |
| 停掉整个后台 | 双击 `暂停后台.cmd` | — |
| 重新拉起后台 | 双击 `启动后台.cmd` | — |
| 解除持久化暂停 | 网页「反代」页 → 恢复 | 正常自动起 |

**「暂停」和「停止」的区别**：暂停的状态写进设置，重启后台也不会自动启动反代，
要手动点恢复。

## 6. 开机自启

```cmd
cd versions\v4
scripts\install-task.cmd
```

注册 Windows 计划任务 `TeleAgent Proxy V4`，用 `ONLOGON` 触发，
以当前用户身份运行（不需要管理员权限）。

进程不随终端关闭而结束 —— 这是计划任务相对「双击 cmd」的优势。

## 7. 跨机迁移

### 源机

```
「账号」页 → 导出 → 选 bundle → 得到 account-YYYY-MM-DD.bundle
```

bundle 含 token + 渠道密钥（+ 可移植账号的 local-key）。

### 目标机

```
① 把整个 versions/v4 文件夹 + bundle 拷过去
② 双击 启动后台.cmd
③ 「账号」页 → 导入 → 选那个 bundle
④ 「反代」页 → 启动
```

目标机**不需要装 TeleAgent**，不需要 `npm install`，只要 Node 18+。

## 8. 目录与数据

```
versions/v4/
├─ bin/tav3.js          入口
├─ lib/                 源码
├─ config/
│  ├─ settings.json     设置（网页上改这里）
│  └─ channel-key.txt   渠道密钥（迁移时带上）
├─ data/                ← 运行时数据，别删
│  ├─ accounts.json     加密的账号库
│  ├─ .key              加密密钥
│  ├─ requests.log      请求摘要（调试用）
│  └─ requests.responses.log  上游响应记录
├─ scripts/             安装任务、测试脚本
├─ 启动后台.cmd
└─ 暂停后台.cmd
```

> **`data/` 目录是续期链的命根子。** 删了凭证就断了，
> 所有账号都要重新登录 + 重新扫描。

## 9. 对外监听（局域网）

默认只听 `127.0.0.1`。要局域网访问：

```
Web 后台「设置」页 → proxy.host 改成 0.0.0.0
```

或者 v2 的环境变量方式：

```cmd
set TA_HOST=0.0.0.0
set TA_API_KEY=你的密钥
```

> ⚠️ **改成 `0.0.0.0` 意味着任何人都能操作你的账号。**
> 一定要同时设一个强 `apiKey`，并确认防火墙规则。

## 10. 日志

| 位置 | 内容 |
|---|---|
| Web 后台「日志」页 | 实时日志，每 4 秒刷新，内存里保留最近 500 条 |
| `data/requests.log` | 请求摘要：模型、stream、消息结构、媒体类型 |
| `data/requests.responses.log` | 上游响应：状态码、错误码、原始报文片段 |

`requests.log` 只记摘要不记完整 body，但足以回答「客户端到底发了什么」。

## 11. 自检

v2 及以后有 `doctor` 命令：

```cmd
node bin\tav3.js doctor
```

检查项：Node 版本、端口占用、账号状态、渠道密钥、数据目录可写性。

v4 的验收脚本：

```cmd
node scripts\test-full.js     # 13 项全功能验收
node scripts\test-web.js      # 30 项 Web 后台回归
```

## 12. 升级

四个版本各自独立，直接换目录即可：

```cmd
:: 停掉旧版
双击 暂停后台.cmd
（或 schtasks /End /TN "TeleAgent Proxy V3"）

:: 换目录
cd versions
git pull                     （monorepo 下）

:: 起新版
cd v4
双击 启动后台.cmd
```

> ⚠️ **跨版本迁移账号数据**：v3 → v4 的 `data/` 目录格式一致，
> 可以直接拷。但 v3 和 v4 **不要同时跑同一个账号**。
